# Safex 传感器及外设模块规格说明书

> **文档版本**: 6.0  
> **编写日期**: 2026-07-02  
> **适用平台**: Air8000A (LuatOS, Lua 5.3)  
> **来源**: 从 STM32L431RCT6 移植

## 1. 概述

本文档定义从 STM32 移植到 Air8000A 的传感器及外设模块规格。Air8000 作为主控负责传感器采集、报警判定、IO 控制和串口屏驱动。

### 1.1 移植范围

| 模块 | STM32引脚 | Air8000A引脚 | 接口 | 移植状态 |
|------|----------|-------------|------|---------|
| PID 光离子化传感器 | PA4 (ADC1_IN9) | ADC0 (pin 75) | ADC | ✅ 已完成 |
| IMS 离子迁移谱 | PB10/PB11 (USART3) | UART12 (pin 60/59) | UART | ✅ 已完成 |
| 电池电压监控 | PC3 (ADC1_IN4) | ADC2 (pin 42) | ADC | ✅ 已完成 |
| 报警管理 | — | — | 逻辑 | ✅ 已完成 |
| LED 指示灯 ×3 | PA15, PB5, PC13 | UART10 (pin 57/58) | UART | ✅ 已完成 |
| 蜂鸣器 | PB8 | GPIO16 (pin 83) | GPIO | ✅ 已完成 |
| 按键 ×3 | PB0, PB1, PB2 | GPIO153/147/146 (pin 52/53/54) | WGPIO | ✅ 已完成 |
| TJC 陶晶池串口屏 | — | UART11 (pin 57/58) | UART | ✅ 已完成 |
| Flash 存储 | PA5-PA8 (SPI1) | SPI1 (pin 38-41) | 硬件 SPI | ✅ 已完成 |

### 1.2 不移植模块

| 模块 | 原因 |
|------|------|
| — | （W25Q64 外部 Flash 已移植至 SPI1） |
| SWD 调试 | STM32 本地烧录调试 |

### 2.3 调度策略

- 传感器采集周期：1 秒
- 每个采集周期内依次读取：PID → IMS → 电池
- 报警判定在每个采集周期后执行，联动 LED 和蜂鸣器
- 按键使用中断触发 + 50ms 消抖
- 串口屏由事件驱动（数据更新时刷新）
- Flash 按需写入（报警记录、浓度数据）

## 3. PID 光离子化传感器 (mod_pid)

### 3.1 硬件接口

| 项目 | 值 |
|------|------|
| Air8000A 引脚 | ADC0 (pin 75) |
| LuatOS ADC 通道 | 0 |
| STM32 对应 | PA4 / ADC1_IN9 |
| 采样精度 | 12-bit (0-4095) |

### 3.2 功能需求

| 编号 | 需求 | 优先级 | 状态 |
|------|------|--------|------|
| FR-PID-01 | 通过 ADC0 读取 PID 传感器原始值 | 高 | ✅ |
| FR-PID-02 | 将 ADC 原始值转换为电压 (V) | 高 | ✅ |
| FR-PID-03 | 将电压转换为浓度 (ppm)，公式: conc = voltage × 100 | 高 | ✅ |
| FR-PID-04 | 浓度 > 50.0 ppm 时触发报警标志 | 高 | ✅ |
| FR-PID-05 | 通过 config 开关 `sensor_pid_en` 控制采集 | 中 | ✅ |

### 3.3 数据字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `pid_conc` | number | 浓度 (ppm) |
| `pid_raw_adc` | number | ADC 原始值 (0-4095) |
| `pid_voltage` | number | 电压 (V) |
| `pid_alarm` | bool | 是否报警 |
| `timestamp` | number | 采集时间戳 |

### 3.4 接口

```lua
mod_pid.init()              -- 初始化 ADC
mod_pid.read()              -- 读取一次，返回 conc, raw_adc, voltage, alarm
```

## 6. 报警管理器 (mod_alarm)

### 6.1 报警逻辑

参考 STM32 `sensor_mgr.c` 中的报警判定逻辑：

| 条件 | 报警等级 | 说明 |
|------|---------|------|
| PID 报警 | 2 (警告) | PID 传感器报警 |
| IMS 检测到毒剂 | 3 (严重) | 毒剂检测直接严重报警 |
| 蓝牙污染源 RSSI 超阈值 | 2/3 (警告/严重) | 根据信号强度计算报警等级 |
| 无报警 | 0 (正常) | — |

### 6.2 功能需求

| 编号 | 需求 | 优先级 | 状态 |
|------|------|--------|------|
| FR-ALARM-01 | 读取 PID/IMS 报警标志 | 高 | ✅ |
| FR-ALARM-02 | 计算综合报警等级 (0/2/3) | 高 | ✅ |
| FR-ALARM-03 | 报警等级变化时通知 app_data | 高 | ✅ |
| FR-ALARM-04 | 报警等级 ≥2 时驱动蜂鸣器鸣响 | 高 | ✅ |
| FR-ALARM-05 | 报警等级 =3 时蜂鸣器连续鸣响 | 高 | ✅ |
| FR-ALARM-06 | 报警等级 =2 时蜂鸣器间歇鸣响 | 中 | ✅ |
| FR-ALARM-07 | 驱动 LED_ALARM 指示灯 | 高 | ✅ |
| FR-ALARM-08 | 蓝牙模块接收模拟污染源广播，根据 RSSI 计算报警等级 | 高 | ✅ |

### 6.3 数据字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `alarm_level` | number | 报警等级 (0=正常, 2=警告, 3=严重) |
| `alarm_source` | string | 报警来源 ("pid"/"ims"/"fall"/"ble"/"none") |
| `timestamp` | number | 最后更新时间 |

## 7. LED 指示灯控制 (mod_led)

### 7.1 硬件接口

| LED | Air8000A 引脚 | LuatOS UART | 功能 | 驱动方式 |
|-----|-------------|-------------|------|---------|
| LED ×3 (红/黄/绿) | UART10_TX (pin 57), UART10_RX (pin 58) | UART10 | 电源/报警/通信三色灯 | UART10 单字节指令协议 |

- **灯珠配置**: 红灯、黄灯、绿灯（外部 LED 控制板）
- **驱动方式**: 通过 UART10 向外部 LED 控制板发送 1 字节指令，控制红/黄/绿三色 LED
- **通信参数**: 115200, 8N1, 无校验，帧格式为 1 字节指令

**指令表**:

| 指令码 | 说明 |
|--------|------|
| 0x00 | 熄灭（灯全灭） |
| 0x01 | 红灯常亮 |
| 0x02 | 红灯闪烁（500ms 亮 / 500ms 灭） |
| 0x03 | 黄灯常亮 |
| 0x04 | 黄灯闪烁（500ms 亮 / 500ms 灭） |
| 0x05 | 绿灯常亮 |
| 0x06 | 绿灯闪烁（500ms 亮 / 500ms 灭） |

### 7.2 功能需求

| 编号 | 需求 | 优先级 | 状态 |
|------|------|--------|------|
| FR-LED-01 | 初始化 UART10，115200 8N1 | 高 | ✅ |
| FR-LED-02 | LED 状态映射为指令码并发送 | 高 | ✅ |
| FR-LED-03 | 报警灯跟随报警等级：0=灭, 2=闪烁, 3=常亮（红/黄） | 高 | ✅ |
| FR-LED-04 | 电源灯常亮（绿色） | 高 | ✅ |
| FR-LED-05 | 通信灯通信时闪烁 | 中 | ✅ |
| FR-LED-06 | 提供 `set(name, state)` 接口 | 高 | ✅ |

### 7.3 接口

```lua
mod_led.init()                      -- 初始化 UART10
mod_led.set("power", true)          -- 设置电源灯亮
mod_led.set("alarm", "blink_fast")  -- 报警灯快闪
mod_led.set("comm", "blink_slow")   -- 通信灯慢闪
mod_led.set("comm", false)          -- 通信灯灭
```

## 11. Flash 存储 (mod_flash)

### 11.1 硬件接口

| 信号 | Air8000A 引脚 | LuatOS GPIO | 功能 |
|------|-------------|-------------|------|
| SPI_SCK | pin 38 (SPI1_SCLK) | GPIO15 | NAND SPI 时钟 |
| SPI_MISO | pin 39 (SPI1_MISO) | GPIO14 | NAND SPI MISO |
| SPI_MOSI | pin 40 (SPI1_MOSI) | GPIO13 | NAND SPI MOSI |
| NAND_CS | pin 55 (GPIO141) | GPIO141 | NAND 片选 |
| NOR_CS | pin 41 (SPI1_CS) | GPIO12 | NOR 片选 (待实现) |

- **SPI 类型**: 硬件 SPI1，NAND 和 NOR 共享 SCK/MISO/MOSI，CS 独立
- **NAND 芯片**: TM3F1GUAI (1Gbit / 128MB SPI NAND)
- **NAND CS**: GPIO141 (pin 55, WGPIO)
- **NOR CS**: GPIO12 (pin 41, SPI1_CS)
- **时钟频率**: 2MHz (稳定可靠)
- **驱动库**: LuatOS `little_flash` (`lf`) — 自动坏块管理 + ECC 纠错
- **文件系统**: LittleFS (通过 `lf.mount` 挂载)

### 11.2 功能需求

|------|------|--------|------|

| FR-FLASH-04 | 提供报警记录写入 | 高 | ✅ |
| FR-FLASH-05 | 提供日志记录写入 | 低 | ✅ |

## 11.5 蓝牙污染源检测 (mod_ble) — ✅ 已实现

### 硬件接口

| 信号 | Air8000A 引脚 | LuatOS UART | 方向 | 功能 |
|------|-------------|-------------|------|------|
| TX | pin 16 | UART1_TXD | 输出 | TX → MY-BT503 |
| RX | pin 17 | UART1_RXD | 输入 | RX ← MY-BT503 |

- **蓝牙模块**: MY-BT503-S（外部蓝牙模块，非 Air8000 内置 BLE）
- **波特率**: 115200, 8N1

### 功能说明

蓝牙模块通过 UART1 AT 指令方式扫描周围蓝牙设备，利用 iBeacon 广播数据实现虚拟化学污染源检测：

1. **AT 握手**: MCU 发送 `AT`，等待 `OK` 确认模块在线
2. **AT+SCAN=2**: 握手成功后发送一次 `AT+SCAN=2`，模块回复 `OK` 后开始持续返回 `+SCAN` 广播数据
3. **iBeacon 解析**: 从 `+SCAN` 的广播数据中解析 iBeacon 帧（Company ID `4C00` → UUID → Major → Minor）
4. **UUID 过滤**: 检查 UUID 是否匹配 Safex 固定标识，不匹配则静默忽略（非 Safex 污染源）
5. **Major 匹配**: 根据 Major 值查询污染源路由表（fskv 持久化，预置 9 种毒剂，可通过网页管理）
6. **RSSI → 浓度映射**: 线性映射 `rssi_near → max_conc`，`rssi_far → 0`
7. **报警联动**: 浓度超 `warn_conc` 阈值触发严重报警（等级 3）— **暂未实现，预留**

### AT+SCAN=2 返回格式

模块返回逗号分隔的数据行：

```
+SCAN=<param1>,<param2>,<param3>,<param4>,<param5>,<param6>\r\n
```

| 参数 | 字段 | 说明 | 示例 |
|------|------|------|------|
| param1 | MAC 地址类型 | 0=公共, 1=随机 | `0` |
| param2 | MAC 地址 | 12 位 hex 字符串 | `AB0A2024130C` |
| param3 | RSSI | 信号强度 (dBm) | `-65` |
| param4 | 广播类型 | 广播数据类型 | `1` |
| param5 | 广播长度 | param6 的字节长度 | `60` |
| param6 | 广播内容 | hex 字符串 | `0201061AFF4C00...` |

### iBeacon 帧结构

param6 中包含 iBeacon 数据，标准格式如下：

```
02 01 06          — Flags (3字节, 固定)
1A FF 4C00        — ManufacturerData 头 (长度=26, 类型=0xFF, CompanyID=Apple 0x4C00)
02 15             — iBeacon 类型(02) + 数据长度(15=21字节)
[UUID  16字节]    — 污染源统一标识
[Major 2字节]     — 污染源类型编码
[Minor 2字节]     — 污染源编号
[TX Power 1字节]  — 校准发射功率
```

### 污染源命名规则

#### UUID（统一标识）

所有 Safex 污染源设备使用**同一个固定 UUID**，作为"Safex 污染源"的识别标记：

```
UUID = 5B198FF2-69A0-11EE-8C99-0242AC120002
```

MCU 扫描到 iBeacon 后，先检查 UUID 是否匹配，不匹配的直接忽略（过滤掉普通 iBeacon 设备）。

#### Major（污染源类型编码）

Major 用于区分不同毒剂类型，2 字节（`0001`~`FFFF`）：

| Major | 类型 | 化学缩写 | 说明 |
|-------|------|---------|------|
| `0x0001` | 沙林毒剂 | GB | 神经性毒剂 |
| `0x0002` | 芥子气 | HD | 糜烂性毒剂 |
| `0x0003` | 氯气 | CL | 窒息性毒剂 |
| `0x0004` | 氰化氢 | HCN | 血液性毒剂 |
| `0x0005` | 光气 | CG | 窒息性毒剂 |
| `0x0006` | 路易氏剂 | L | 糜烂性毒剂 |
| `0x0007` | 塔崩 | GA | 神经性毒剂 |
| `0x0008` | VX 毒剂 | VX | 神经性毒剂 |
| `0x0009`~`0xFFFE` | 保留 | — | 可扩展 |
| `0xFFFF` | 测试 | — | 用于自检/演示 |

#### Minor（污染源编号）

Minor 用于区分同类型的不同设备，2 字节（`0001`~`FFFF`）：

| Minor | 说明 | 示例 |
|-------|------|------|
| `0x0001` | 同类型第 1 号设备 | 沙林源 1 号 |
| `0x0002` | 同类型第 2 号设备 | 沙林源 2 号 |
| `0x0003` | 同类型第 3 号设备 | 沙林源 3 号 |
| ... | 可扩展 | |

#### TX Power（校准值）

1 字节，用于距离估算校准，固定为 `0xB5`（-59 dBm）。不用于污染源匹配。

### 污染源设备配置示例

部署时，每个污染源蓝牙模块通过 AT 指令设置 iBeacon 广播数据：

```bash
# 沙林毒剂 1 号设备
AT+ADVDATA=4C000215 5B198FF269A011EE8C990242AC120002 0001 0001 B5
                                            ↑UUID(固定)  ↑Major ↑Minor

# 芥子气 1 号设备
AT+ADVDATA=4C000215 5B198FF269A011EE8C990242AC120002 0002 0001 B5
                                            ↑UUID(固定)  ↑Major ↑Minor

# 氯气 3 号设备
AT+ADVDATA=4C000215 5B198FF269A011EE8C990242AC120002 0003 0003 B5
                                            ↑UUID(固定)  ↑Major ↑Minor
```

> **注意**: `AT+ADVDATA` 设置后需要重启模块或触发重新广播才能生效。

### 污染源路由表结构

每条路由配置一种已知污染源类型（按 Major 匹配）。系统预置 9 条默认路由，用户可通过网页增删改：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `major` | number | 污染源类型编码（Major 值） | `1` |
| `type` | string | 污染源类型描述 | `"沙林毒剂"` |
| `rssi_near` | number | 近距离 RSSI 阈值（对应 max_conc） | `-30` |
| `rssi_far` | number | 远距离 RSSI 阈值（对应 0 浓度） | `-80` |
| `max_conc` | number | 最大浓度值 (ppm) | `100` |
| `warn_conc` | number | 预警浓度阈值 (ppm) | `50` |

### RSSI → 浓度映射公式

```
conc = max_conc × (rssi - rssi_far) / (rssi_near - rssi_far)
```

- RSSI ≥ rssi_near → conc = max_conc（最近距离）
- RSSI ≤ rssi_far → conc = 0（最远距离/无信号）
- 介于两者之间 → 线性映射

### MCU 解析流程

```
1. AT+SCAN=2 发送一次，之后持续读取 +SCAN 数据
2. 解析 +SCAN 行，提取 MAC、RSSI、广播数据(advdata)
3. 在 advdata 中搜索 "4C000215" (Apple Company ID + iBeacon 标记)
4. 提取 UUID，检查是否匹配固定标识 → 不匹配则静默忽略
5. 提取 Major，查路由表 → 不在路由表则静默忽略
6. 提取 Minor（设备编号）
7. 用 RSSI + 路由表参数线性映射浓度
8. 更新 ble.sources 列表（按 major+minor 去重）
9. 报警联动 → 暂未实现
```
