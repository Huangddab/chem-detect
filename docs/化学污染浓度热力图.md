# Safex 化学污染浓度热力图方案

> 版本：v2.0 | 日期：2026-09-03
> 关联文档：[多设备组网与训练模式.md](多设备组网与训练模式.md) 第 2 章

---

## 1. 概述

热力图用于在地图上可视化展示区域内化学污染浓度的分布态势。采用 **指挥官集中计算** 架构：

- **成员设备**：每轮上报一个浓度采样点（位置 + 浓度 + 来源）
- **指挥官设备**：收集同组成员采样点，在 MCU 本地运行网格聚类，输出热力图数据
- **服务端（可选）**：接收指挥官上报的聚合结果，做历史存储和前端渲染

```
成员A ──┐
成员B ──┤── MQTT 上报采样点 ──→ 指挥官 本地网格聚合 ──→ 指挥官上报 heatmap.points
成员C ──┘                                                    │
                                                              ▼
                                                        服务端 / 前端渲染
```

### 1.1 为什么只用指挥官计算

| 对比项 | 全员计算 | 仅指挥官计算（本方案） |
|--------|---------|----------------------|
| CPU 占用 | N 台 × N 次循环 | 1 台 × N 次循环 |
| 数据一致性 | 各算各的，结果不一致 | 统一计算，结果唯一 |
| 流量消耗 | 每台都上报聚合结果 | 只有指挥官上报聚合结果 |
| 成员负担 | 每台都要算 | 成员只管采样上报，省电省 CPU |
| 单点故障 | 无 | 指挥官离线 → 热力图暂停（可接受） |

### 1.2 指挥官离线降级策略

- 指挥官离线 → 热力图计算暂停，`heatmap.points` 保持最后一次结果
- 指挥官重新上线 → 重新聚合
- 用户可手动指定新指挥官继续计算
- 成员设备始终正常上报采样点，不受影响

## 2. 成员设备采样

### 2.1 采样点数据结构

每台成员设备每次 MQTT 上报时，从当前传感器数据动态构建一个采样点：

```json
{
    "heatmap": {
        "sample": {
            "lat": 22.54310,
            "lng": 113.83615,
            "conc": 42,
            "source": "pid",
            "timestamp": 1725360000
        }
    }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `lat` | number | 设备当前纬度（十进制，来自 GNSS） |
| `lng` | number | 设备当前经度（十进制，来自 GNSS） |
| `conc` | number | 综合浓度值 (ppm)，0 表示无污染 |
| `source` | string | 浓度来源：`"ims"` / `"pid"` / `"ble"` / `"none"` |
| `timestamp` | number | 采样时间戳 (Unix) |

### 2.2 浓度优先级

当多个传感器同时检测到数据时，按优先级取最高浓度：

| 优先级 | 来源 | 条件 | 浓度取值 |
|--------|------|------|---------|
| 1 | IMS | `ims.alarm_count > 0`（检测到毒剂） | 100（满浓度） |
| 2 | PID | `pid.conc > 0`（PID 浓度 > 0） | `pid.conc` |
| 3 | BLE | `ble.max_conc > 0`（虚拟污染源浓度） | `ble.max_conc` |
| 4 | none | 以上均无 | 0 |

> **IMS 优先**：IMS 是离子迁移谱，能直接识别毒剂类型，检测到毒剂时标记为满浓度 100，表示该位置存在确定的化学威胁。
> **PID 次之**：PID 是光离子化检测器，测量 VOC 总浓度，不能区分毒剂类型但浓度值精确。
> **BLE 最低**：BLE 虚拟污染源是基于 iBeacon RSSI 映射的模拟浓度，精度最低。

### 2.3 成员设备不存历史数据

采样点在每次上报时**动态构建**，不长期存储。历史聚合由指挥官负责。

## 3. 指挥官本地网格聚合

### 3.1 数据来源

指挥官通过 MQTT 通配符订阅 `safex/+/status`，收到的每条消息中包含采样点数据。指挥官将同组在线成员的采样点存入 `group_info.members` 表（含 `lat`, `lng`, `concentration` 字段），作为聚合输入。

### 3.2 网格大小

Air8000 MCU 算力有限，采用**固定粗粒度网格**，不做动态缩放：

| 网格参数 | 值 | 说明 |
|---------|-----|------|
| 网格精度 | `0.001°` | 纬度/经度各保留 3 位小数 |
| 网格尺寸 | 约 100m × 100m | 在中纬度地区约 111m × 111m |
| 网格编号 | `floor(lat * 1000)` / `floor(lng * 1000)` | 整数索引 |

> **计算量评估**：50 台设备 × 遍历 1 次 = 50 次循环，每次做 2 次乘法 + 2 次取整 + 1 次比较。Air8000 不到 1ms 完成。

### 3.3 聚合算法

```lua
-- 指挥官本地网格聚合（伪代码）
local function compute_heatmap(members)
    local grids = {}  -- 临时网格表 {[grid_key] = {lat=, lng=, conc=, count=}}

    for device_id, m in pairs(members) do
        -- 跳过离线和浓度=0的设备
        if m.online and m.concentration > 0 then
            -- 计算网格编号
            local grid_lat = math.floor(m.lat * 1000)
            local grid_lng = math.floor(m.lng * 1000)
            local key = grid_lat .. "_" .. grid_lng

            if not grids[key] then
                grids[key] = {
                    lat   = grid_lat / 1000,   -- 网格中心纬度
                    lng   = grid_lng / 1000,   -- 网格中心经度
                    conc  = m.concentration,   -- 取第一个浓度
                    count = 1,
                }
            else
                -- 同网格取最大浓度（保守策略，避免漏报）
                if m.concentration > grids[key].conc then
                    grids[key].conc = m.concentration
                end
                grids[key].count = grids[key].count + 1
            end
        end
    end

    -- 转换为数组输出
    local points = {}
    for _, g in pairs(grids) do
        table.insert(points, {
            lat   = g.lat,
            lng   = g.lng,
            conc  = g.conc,
            count = g.count,
        })
    end
    return points
end
```

### 3.4 聚合规则

| 规则 | 说明 |
|------|------|
| 网格分组 | 同 `0.001°` 方格内的设备归为一点 |
| 浓度取值 | 同网格取**最大浓度**（保守策略，避免漏报） |
| 无效过滤 | `conc = 0` 或 `online = false` 的设备跳过 |
| 网格中心 | 输出坐标 = 网格编号 / 1000（如 `22543 / 1000 = 22.543`） |
| 设备计数 | `count` 字段记录该网格内有几台设备 |

### 3.5 聚合示例

```
原始采样点（3 台在线成员）:                     聚合后:
  A (22.5431, 113.8362, conc=42, online=true)  ─┐
  B (22.5435, 113.8368, conc=15, online=true)  ─┘→ 网格1: (22.543, 113.836, conc=42, count=2)
  C (22.6012, 113.9001, conc=100, online=true) ──→ 网格2: (22.601, 113.900, conc=100, count=1)
  D (22.5500, 113.8400, conc=0, online=true)   ──→ 丢弃 (conc=0)
  E (22.5600, 113.8500, conc=80, online=false) ──→ 丢弃 (离线)
```

### 3.6 触发时机

- 指挥官每收到一轮成员状态更新后触发一次聚合
- 即每 `report_interval` 秒（默认 2-3 秒）聚合一次
- 聚合结果写入 `app_data` 的 `heatmap.points`

## 4. 指挥官上报聚合结果

### 4.1 上报内容

指挥官在 MQTT 定时上报时，`heatmap` 字段从"单点采样"切换为"聚合点列表"：

```json
{
    "heatmap": {
        "points": [
            {"lat": 22.543, "lng": 113.836, "conc": 42, "count": 2},
            {"lat": 22.601, "lng": 113.900, "conc": 100, "count": 1}
        ],
        "device_count": 3,
        "timestamp": 1725360060
    }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `points` | array | 聚合后的热力图点列表 |
| `points[].lat` | number | 网格中心纬度 |
| `points[].lng` | number | 网格中心经度 |
| `points[].conc` | number | 该网格最大浓度 (ppm) |
| `points[].count` | number | 该网格内设备数 |
| `device_count` | number | 参与聚合的在线设备总数 |
| `timestamp` | number | 聚合时间戳 (Unix) |

### 4.2 上报区别

| 设备角色 | heatmap 上报内容 | 说明 |
|---------|-----------------|------|
| 成员设备 | `heatmap.sample = {lat, lng, conc, source, ts}` | 单个采样点 |
| 指挥官设备 | `heatmap.points = [{lat, lng, conc, count}, ...]` | 聚合后多点列表 |

### 4.3 上报 JSON 示例

**成员设备（正常巡逻，无污染）**：
```json
{
    "heatmap": {
        "sample": {
            "lat": 22.54310,
            "lng": 113.83615,
            "conc": 0,
            "source": "none",
            "timestamp": 1725360000
        }
    }
}
```

**指挥官（3 台成员，2 个网格有污染）**：
```json
{
    "heatmap": {
        "points": [
            {"lat": 22.543, "lng": 113.836, "conc": 42, "count": 2},
            {"lat": 22.601, "lng": 113.900, "conc": 100, "count": 1}
        ],
        "device_count": 3,
        "timestamp": 1725360060
    }
}
```

## 5. 数据流

```
┌──────────────────────────────────────────────────────────────────┐
│  成员设备 (Air8000)                                               │
│                                                                  │
│  GNSS ──→ lat, lng                                               │
│  PID  ──→ conc (ppm)          ┌──────────────────┐              │
│  IMS  ──→ alarm_count          │  采样点构建       │              │
│  BLE  ──→ max_conc      ──→   │  (优先级: IMS>PID │ ──→ MQTT 上报  │
│                               │   >BLE>none)      │    sample 点  │
│                               └──────────────────┘              │
└──────────────────────────────────────────────────────────────────┘
        │  MQTT publish: safex/<device_id>/status
        ▼
┌──────────────────────────────────────────────────────────────────┐
│  指挥官设备 (Air8000, is_commander=true)                          │
│                                                                  │
│  ┌─────────────┐     ┌──────────────┐     ┌────────────────┐    │
│  │ 收集成员状态  │ ──→│  本地网格聚合  │ ──→│ heatmap.points  │──→ MQTT 上报
│  │ (members表)  │     │  (0.001°网格) │     │  (聚合点列表)    │    聚合结果
│  │ 过滤离线/零浓度│     │  取最大浓度   │     └────────────────┘    │
│  └─────────────┘     └──────────────┘                            │
│                                                                  │
│  同时也上报自身 sample 点（指挥官自身也是采样设备）                  │
└──────────────────────────────────────────────────────────────────┘
        │  MQTT publish: safex/<commander_id>/status
        │  (payload 含 heatmap.points 而非 heatmap.sample)
        ▼
┌──────────────────────────────────────────────────────────────────┐
│  服务端 (可选)                                                     │
│                                                                  │
│  ┌────────────┐  ┌──────────────┐  ┌────────────┐               │
│  │ 历史存储     │  │ 时间序列回放  │  │ 前端推送    │ → 热力图渲染   │
│  │ (聚合结果)   │  │ (按时间段)   │  │ (WebSocket)│               │
│  └────────────┘  └──────────────┘  └────────────┘               │
└──────────────────────────────────────────────────────────────────┘
```

## 6. 数据结构（app_data.lua）

### 6.1 heatmap 数据结构

```lua
heatmap = {
    -- 当前采样点（所有设备都有，每轮动态构建）
    sample = {
        lat       = 0,
        lng       = 0,
        conc      = 0,
        source    = "none",
        timestamp = 0,
    },
    -- 聚合点列表（仅指挥官维护，网格聚合结果）
    points = {
        -- {lat=22.543, lng=113.836, conc=42, count=2}, ...
    },
    -- 聚合元数据（仅指挥官）
    device_count = 0,    -- 参与聚合的在线设备数
    timestamp    = 0,
},
```

### 6.2 上报逻辑

`get_report_data()` 中根据角色上报不同内容：

```lua
-- 成员设备：上报单个采样点
-- 指挥官设备：上报聚合点列表
if data.group_info.is_commander then
    report.heatmap = {
        points       = data.heatmap.points,
        device_count = data.heatmap.device_count,
        timestamp    = data.heatmap.timestamp,
    }
else
    report.heatmap = {
        sample = {
            lat       = data.heatmap.sample.lat,
            lng       = data.heatmap.sample.lng,
            conc      = data.heatmap.sample.conc,
            source    = data.heatmap.sample.source,
            timestamp = data.heatmap.sample.timestamp,
        }
    }
end
```

## 7. 浓度颜色映射

热力图渲染时（服务端/前端负责），浓度到颜色的映射规则：

| 浓度范围 (ppm) | 颜色 | 含义 |
|----------------|------|------|
| 0 | 不显示 | 无污染 |
| 1-20 | 蓝色 | 低浓度，提示 |
| 21-50 | 绿色 | 中等浓度，注意 |
| 51-80 | 黄色 | 较高浓度，警告 |
| 81-100 | 红色 | 高浓度/毒剂，危险 |

> 颜色渲染在服务端/前端完成，MCU 只输出 `{lat, lng, conc, count}` 数据点。

## 10. 扩展方向

- **历史回放**：服务端存储指挥官上报的聚合结果时间序列，支持按时间段回放热力图变化
- **浓度衰减**：指挥官聚合时对旧数据按时间衰减（如 5 分钟后浓度 ×0.5），模拟污染扩散
- **多源叠加**：同网格内多台设备检测到不同浓度时，可取平均或加权（当前取最大值）
- **预警区域**：指挥官发现浓度超阈值的网格时，自动圈定警戒区域，推送给所有成员
- **屏幕本地显示**：指挥官设备将聚合结果推送到屏幕离线地图上，用颜色标记各网格污染等级
