## 2. 系统总体设计

### 2.1 架构概览 — 星型架构

```
                    main.lua（入口 + 模块加载）
                         │
         ┌───────────────┼───────────────┐
         │               │               │
    ┌────▼────┐    ┌────▼────┐
    │ mod_wdt │    │mod_sensor│
    │ 看门狗   │    │传感器调度│
    └────┬────┘    └────┬────┘
         │               │
    ┌────┬────┬────┬────┬────┬────┬────┬────┐
    │mod │mod │mod │mod │mod │mod │mod │mod │
    │_led│_buz│_key│_gsr│_ble│_gnss│_mqtt│_ota│
    └──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┘
       │    │    │    │    │    │    │    │
       ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼
    ┌──────────────────────────────────────────┐
    │              app_data.lua                  │
    │          数据中心（统一数据管理）           │
    │  config / sys / sensor / alarm / io /     │
    │  ble / gnss / gsensor / mqtt / ota / map  │
    ├──────────────────────────────────────────┤
    │  UART11 串口屏 (TJC 协议)                  │
    │  HTTP 路由 (OTA/文件传输)                  │
    └──────────────────────────────────────────┘
```

### 2.2 设计原则

1. **星型架构** — `app_data` 是中心节点，各模块只与 `app_data` 交互，模块间禁止直接 `require`
2. **功能开关** — 所有功能通过 `config` 表控制，持久化到 fskv，掉电不丢失
3. **数据过滤** — 功能关闭后对应数据不出现在上报 JSON 中
4. **非阻塞** — 全程使用协程 + `sys.wait()`，无阻塞调用
5. **故障恢复** — 分级处理，轻微故障继续运行，严重故障看门狗复位
6. **只读代理** — `app_data.get()` 返回只读代理，写入必须用 `update_xxx()` 接口
7. **回调中介** — 模块间功能调用通过 `register_callback` / `get_callback` 中介

| `mqtt` | `mqtt_en=true` 时上报 |
| `ota` | `ota_en=true` 或 `state≠"idle"` 时上报 |
| `sensor` | `sensor_report_en=true` 时上报（含 pid/ims/battery 子表按各自开关过滤） |
| `alarm` | `alarm_en=true` 时上报 |
| `io` | 各子表按对应开关过滤 |

## 5. 通信协议规格

### 5.1 UART1 — 蓝牙模块通信

UART1 用于与外部蓝牙模块（MY-BT503）通信。

### 5.2 UART11 — TJC 串口屏协议

详见 [通信协议文档.md](通信协议文档.md) 第十一章

### 5.3 UART12 — IMS 离子迁移谱协议

- 帧格式: `AA + 目标(1) + 源(1) + 功能码(1) + 数据长度(2,LE) + 数据(N) + CRC16(2,LE) + 0D 0A`
- 地址: 上位机=1, 下位机=2
- 详见 [传感器及外设规格.md](传感器及外设规格.md)

## 6. 接口规格

### 6.1 app_data 对外接口

| 接口 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `app_data.init()` | 无 | 无 | 初始化数据 + fskv 配置加载 |
| `app_data.start()` | 无 | 无 | 启动运行时间更新协程 |
| `app_data.get()` | 无 | 只读代理 | 获取数据（只读，写入用 update_xxx） |
| `app_data.get_config(key)` | 键 | 值 | 获取功能开关 |
| `app_data.set_config(key,value)` | 键,值 | bool | 设置功能开关（自动持久化到 fskv） |
| `app_data.update_ble(devices)` | 设备列表 | 无 | 更新 BLE 数据 |
| `app_data.update_gnss(...)` | 经纬度等 | 无 | 更新 GNSS 数据 |
| `app_data.update_gsensor(...)` | 加速度等 | 无 | 更新 G-sensor 数据 |
| `app_data.update_mqtt(...)` | 连接状态等 | 无 | 更新 MQTT 状态 |
| `app_data.update_ota(...)` | 升级状态等 | 无 | 更新 OTA 状态 |
| `app_data.update_sensor(sub,fields)` | 子表名,字段表 | 无 | 更新传感器子表 (pid/ims/battery) |
| `app_data.update_io(category,fields)` | 子表名,字段表 | 无 | 更新 IO 外设子表 (led/buzzer/key/screen/flash/power) |
| `app_data.update_alarm(source)` | 报警来源 | 无 | 触发报警 |
| `app_data.clear_alarm(source)` | 报警来源 | 无 | 清除报警 |
| `app_data.update_map_state(fields)` | 字段表 | 无 | 更新地图状态 |
| `app_data.register_callback(name,api)` | 名称,回调表 | 无 | 注册模块回调（星型中介） |
| `app_data.get_callback(name)` | 名称 | 表|nil | 获取模块回调 |

### 6.2 模块接口规范

每个模块 `mod_xxx` 必须实现：

| 接口 | 说明 |
|------|------|
| `mod_xxx.init()` | 初始化硬件/库 |
| `mod_xxx.start()` | 启动采集协程 |

模块通过 `app_data.update_xxx()` 写入数据，不直接操作 `data` 表。

> **重要**：`app_data.get()` 返回的是只读代理。哈希表写入会抛出错误，数组表返回拷贝。任何写入操作都必须使用 `update_xxx()` 接口。

## 7. 非功能需求

### 7.1 性能

| 指标 | 要求 |
|------|------|
| UART1 接收延迟 | < 10ms（回调仅缓冲） |
| 上报间隔精度 | ±200ms（轮询粒度） |
| JSON 编码 | 单次 < 50ms |
| 看门狗喂狗周期 | 3000ms ± 100ms |
| Flash 大文件尾部读取 | < 100ms（seek 定位，禁止遍历） |

### 7.2 可靠性

| 场景 | 处理方式 |
|------|---------|
| UART 缓冲区溢出（>1024B） | 清空缓冲区，记录警告 |
| UART 半包超时（>2s） | 丢弃缓冲区，记录警告 |
| 校验失败 | 返回错误，不处理指令 |
| JSON 编码失败 | 记录警告，跳过本次上报 |
| 看门狗超时（>20s 未喂狗） | 系统自动复位 |
| 传输互斥锁泄漏 | 异步失败自动释放 |
| 配置持久化 | fskv 存储，值未变化时跳过写入 |

### 7.3 安全性

| 项目 | 措施 |
|------|------|
| 串口数据校验 | XOR 校验（可选） |
| 缓冲区溢出 | 1024 字节上限保护 |
| 配置项校验 | 未知 key 拒绝写入 |
| 类型转换 | 布尔/数值自动转换 + 类型检查 |
| 传输互斥锁 | 固件/屏幕/文件传输不可同时进行 |
