# Safex 通信协议文档

> 版本：v7.0 | 日期：2026-09-08

## 一、UART1 — 蓝牙模块通信

UART1 用于与外部蓝牙模块（MY-BT503）通信。

| 参数 | 值 |
|------|-----|
| 串口 | UART1 (pin 16 TX / pin 17 RX) |
| 波特率 | 115200 |
| 数据位 | 8 |
| 校验位 | 无 |
| 停止位 | 1 |
| 对端设备 | MY-BT503 外部蓝牙模块 |
| 模块 | `mod_ble.lua` |

> **历史**：UART1 原用于与 STM32 主控通过 `$SAFE` 协议通信，后改为蓝牙模块通信。`$SAFE` 帧格式、CFG/GET 指令、定时上报、XOR 校验等均已从 `app_data.lua` 中移除。

## 十一、屏幕通信协议 (UART11)

> 适用对象：TJC 陶晶池串口屏工程开发
> 通信接口：UART11 (WGPIO pin 48 RX / pin 49 TX)，115200 8N1
> 详细实现见 `mod_screen.lua`

### 11.1 帧格式

屏幕与 MCU 之间使用 TJC 二进制协议通信，每条指令以 `0xFF 0xFF 0xFF` 结尾。

**屏幕 → MCU（请求）**：

```
0x70  <命令码>  0xFF 0xFF 0xFF
```

- `0x70` = 字符串数据返回标志（TJC `prints` / `printh` 指令）
- `<命令码>` = 1 字节，按半字节编码规则（见 11.2）

**MCU → 屏幕（响应）**：

```
t0.txt="WiFi热点"\xFF\xFF\xFF       — 设置文本控件
n0.val=123\xFF\xFF\xFF             — 设置数值控件
```

### 11.2 命令码编码规则

命令码 1 字节，拆分为高 4 位和低 4 位：

```
    高位 (高4bit)          低位 (低4bit)
    ┌───┴───┐              ┌───┴───┐
    0x   X      Y
         │      │
         │      └── 目标对象
         └── 命令类型
```

**高位 — 命令类型**：

| 高位 | 类型 | 说明 |
|------|------|------|
| `0x0_` | GET | 查询/请求数据（MCU 推送到屏幕） |
| `0x1_` | DIRECT SET | 直接设置（二进制，无参数，低位为序号） |
| `0x2_` | SET | 显式设置（ASCII 带参数） |

**低位 — 目标对象**：

| 低位 | 目标 | 说明 |
|------|------|------|
| `0x_0` | ALL | 全部数据 |
| `0x_1` | SYS | 系统信息 |
| `0x_2` | SENSOR | 传感器数据 |
| `0x_3` | GNSS | GNSS 详情汇总 |
| `0x_4` | RMC | RMC 定位数据 |
| `0x_5` | GSA | GSA 精度因子 |
| `0x_6` | GSV | GSV 卫星可见数 |
| `0x_7` | FIX | 定位状态 |
| `0x_8` | LOC | 位置数据 |
| `0x_9` | CONFIG | 配置（WiFi/蓝牙） |
| `0x_A` | NET_MODE | WiFi 模式 |
| `0x_B` | BLE | 蓝牙开关 |

### 11.3 命令码速查表

#### GET 命令（高位 `0x0_`）

| 命令码 | 屏幕端指令 | 说明 | MCU 响应控件 |
|--------|-----------|------|-------------|
| `0x00` | `printh 70 00 FF FF FF` | 推送全部数据 | 主页全部控件 |
| `0x01` | `printh 70 01 FF FF FF` | 推送系统信息 | uptime, device_id |
| `0x02` | `printh 70 02 FF FF FF` | 推送传感器数据 | pid/ims/battery |
| `0x03` | `printh 70 03 FF FF FF` | GNSS 详情汇总 | t0~t9 (GNSS 页) |
| `0x04` | `printh 70 04 FF FF FF` | RMC 定位数据 | t0~t3 (GNSS 页) |
| `0x05` | `printh 70 05 FF FF FF` | GSA 精度因子 | t4~t5 (GNSS 页) |
| `0x06` | `printh 70 06 FF FF FF` | GSV 卫星数 | t6 (GNSS 页) |
| `0x07` | `printh 70 07 FF FF FF` | 定位状态 | t7 (GNSS 页) |
| `0x08` | `printh 70 08 FF FF FF` | 位置数据 | t8~t9 (GNSS 页) |
| `0x09` | `printh 70 09 FF FF FF` | 推送配置状态 | t0~t1 (设置页) |
| `0x0C` | `printh 70 0C FF FF FF` | 进入寻源模式 | 持续刷新 s0 双波峰图 |
| `0x0D` | `printh 70 0D FF FF FF` | 推送 MQTT 配置 | t3/t4/t5/t6/t8 (设置页) |
| `0x0E` | `printh 70 0E FF FF FF` | 退出寻源模式 | 停止自动刷新 s0 |

#### DIRECT SET 命令（高位 `0x1_`，二进制无参数，推荐）

| 命令码 | 屏幕端指令 | 说明 | MCU 响应 |
|--------|-----------|------|----------|
| `0x10` | `printh 70 10 FF FF FF` | WiFi 关闭 | t0="WiFi OFF", t2/t3/t4 清空 |
| `0x11` | `printh 70 11 FF FF FF` | WiFi STA 模式（MCU 拉取凭据） | MCU 读取 t2/t3 → t0="Connecting..." → 成功后 t4 显示连接信息 |
| `0x12` | `printh 70 12 FF FF FF` | WiFi AP 模式 | t0="Connecting..." → t0="WiFi AP" → t4 显示连接信息 |
| `0x13` | `printh 70 13 FF FF FF` | 蓝牙开启（自动关闭 WiFi） | t0="WiFi OFF", t1="BLE ON" |
| `0x14` | `printh 70 14 FF FF FF` | 蓝牙关闭 | t1="BLE OFF" |
| `0x15` | `printh 70 15 FF FF FF` | 地图开启 | 切换到地图页面 |
| `0x16` | `printh 70 16 FF FF FF` | 地图关闭 | 返回主页面 |
| `0x1B` | `printh 70 1B FF FF FF` | 地图坐标系 WGS84 | 不纠偏，使用 GPS 原始坐标 |
| `0x1C` | `printh 70 1C FF FF FF` | 地图坐标系 GCJ02 | 火星坐标，高德/腾讯（默认） |
| `0x1D` | `printh 70 1D FF FF FF` | 地图坐标系 BD09 | 百度坐标 |
| `0x1E` | `printh 70 1E FF FF FF` | IMS 读取谱库 | 触发 IMS_READ_LIB 事件 |
| `0x1F` | `printh 70 1F FF FF FF` | IMS 切换谱库 | 触发 IMS_SWITCH_LIB 事件 |
| `0x20` | `printh 70 20 FF FF FF` | IMS 跳过预热 | 触发 IMS_SKIP_WARM 事件 |
| `0x21` | `printh 70 21 FF FF FF` | IMS 切换灵敏度 | 触发 IMS_TOGGLE_SENS 事件 |
| `0x22` | `printh 70 22 FF FF FF` | 蜂鸣器响/停 toggle（GPIO 测试） | 直接控制 GPIO16，不受 buzzer_en 限制 |

#### MQTT SET 命令（高位 `0x2_`，二进制无参数）

| 命令码 | 屏幕端指令 | 说明 | MCU 响应 |
|--------|-----------|------|----------|
| `0x23` | `printh 70 23 FF FF FF` | MQTT 连接（MCU 拉取 t3/t4） | t6="Connecting..." → t6 状态更新 |
| `0x24` | `printh 70 24 FF FF FF` | MQTT 断开 | t6="MQTT OFF" |
| `0x25` | `printh 70 25 FF FF FF` | 设置上报间隔（MCU 拉取 t8） | t6="Interval: Ns" |
| `0x26` | `printh 70 26 FF FF FF` | 地图瓦片偏移拉取（MCU 拉取 t5/t6） | 应用偏移后刷新地图 |
| `0x27` | `printh 70 27 FF FF FF` | 地图设备测试拉取（MCU 拉取 t7/t8） | 读取 t7=纬度 t8=经度，刷新 p1 标记（临时测试） |

#### ASCII SET 命令（带参数）

| 指令 | 屏幕端用法 | 说明 |
|------|-----------|------|
| `SET_NET_MODE` | `prints "SET_NET_MODE ap"` | 设置 WiFi 模式 (off/ap/sta) |
| `SET_BLE` | `prints "SET_BLE 1"` | 蓝牙开关 (1=开, 0=关) |
| `SET_BUZZER` | `prints "SET_BUZZER 1"` | 蜂鸣器开关 |
| `SET_MAP_OFFSET` | `prints "SET_MAP_OFFSET gcj02"` | 设置地图坐标系 (wgs84/gcj02/bd09) |

> **地图坐标系说明**：GPS 输出 WGS84 坐标系，不同地图厂商使用不同坐标系，直接使用 WGS84 在国内地图会有 ~500m 偏移。通过 `SET_MAP_OFFSET` 切换坐标系，设置后地图自动刷新。
>
> | 参数 | 坐标系 | 适用地图 |
> |------|--------|----------|
> | `wgs84` | WGS84 (不纠偏) | GPS 原始坐标，Google 国际版 |
> | `gcj02` | GCJ02 火星坐标 | 高德、腾讯、Google 中国区域 (默认) |
> | `bd09` | BD09 百度坐标 | 百度地图 |

> **瓦片微调偏移**：点击屏幕 `b10` 按钮发送 `printh 70 26 FF FF FF`，MCU 主动从屏幕 `t5`（X 偏移）和 `t6`（Y 偏移）读取数值并刷新地图。偏移值仅存内存不写 Flash，方便调试。调试确定后可后续持久化。x 正值右移、负值左移；y 正值下移、负值上移。重置：在 `t5`/`t6` 填 `0` 再点 `b10`。

> **多设备标记**：MCU 通过 MQTT 订阅 `chem/{device_id}/notify`（单发）和 `chem/notify`（群发）主题消息，解析其他设备的 WGS84 坐标存储到 `app_data.map.devices` 列表。地图显示时，各设备位置通过屏幕 `p1`~`p8` 控件（picture 控件）在地图上标记，最多支持 8 个设备。设备坐标同样经过当前坐标系的纠偏处理后定位。收到新坐标时自动刷新标记位置，无需重新加载瓦片。支持两种 payload 格式：
>
> 1. **快照格式（推荐，`type=locations`）**：`devices` 数组为全量在线设备，设备端收到后清空重建列表，**列表中缺席的设备即下线**（自动清除地图标记）。顶层 `timestamp`（秒级，>1e12 按毫秒归一化）用于丢弃 QoS1 积压的过期快照（单调递增检查，不依赖设备本地时钟）：
>
> ```json
> {
>     "type": "locations",
>     "timestamp": 1784024217,
>     "devices": [
>         { "device_id": "860000012345678", "lat": 22.54310, "lng": 113.83615 },
>         { "device_id": "860000012345679", "lat": 22.54321, "lng": 113.83620 }
>     ]
> }
> ```
>
> 2. **单条格式（旧版兼容）**：单设备坐标消息，`device_id` 从主题（单发）或 payload（群发）提取，坐标字段支持 `lat`/`latitude`、`lng`/`lon`/`longitude` 或嵌套 `gnss.lat`/`gnss.lng`。

> **GPS 跟随定位**：`app_data.gnss.lat/lng` 初始为测试坐标（深圳宝安，测试阶段兜底，正式上线前改 0），有定位时由 `update_gnss` 覆盖，定位丢失不清零（保留最后一次有效坐标）。地图开启（0x15）直接以 `gnss.lat/lng` 为中心定位，无额外标志位判断。显示期间由 GPS 跟随循环（1 秒周期）持续跟随：`gnss` 坐标变化超过 `GPS_MOVE_THRESHOLD`（0.0001° ≈ 11 米）才重新加载瓦片，过滤定位噪声；坐标不变时自然不刷新。

> **规则**：屏幕端按钮触发事件代码中，用 `prints`/`printh` 发送对应指令，MCU 统一通过 `REQUEST_HANDLERS` 路由表处理。禁止依赖触控控件 ID 分发业务逻辑。

**STA 模式凭据拉取流程**：

屏幕端只需发 `printh 70 11 FF FF FF`，MCU 收到后主动从屏幕拉取凭据：

```
MCU → 屏幕: get t2.txt    （读取 SSID）
屏幕 → MCU: 0x70 + SSID + 0xFF 0xFF 0xFF
MCU → 屏幕: get t3.txt    （读取密码）
屏幕 → MCU: 0x70 + 密码 + 0xFF 0xFF 0xFF
MCU: 保存凭据 → 防呆验证 → STA 连接 → 推送 t2/t3
```

屏幕端设置页需要以下控件：

| 控件 | 用途 |
|------|------|
| `t0` | WiFi 模式显示（MCU 写） |
| `t1` | 蓝牙开关显示（MCU 写） |
| `t2` | WiFi 名称（用户输入 + MCU 显示） |
| `t3` | WiFi 密码（用户输入 + MCU 显示） |
| `t4` | 网络信息提示（MCU 写，显示 IP 地址和连接说明） |

### 11.4 WiFi/BLE 独立运行

蓝牙模块（MY-BT503）通过 UART1 通信，与 WiFi 独立运行，不占用 Air8000 射频资源。WiFi 和蓝牙可同时工作，无需互斥。

配置变更后，MCU 自动推送最新状态到屏幕设置页控件。

### 11.5 设置页屏幕工程配置

设置页控件配置（在 `mod_screen.lua` 顶部可修改）：

```lua
local CFG_WIDGET_MODE   = "t0"     -- WiFi 模式显示文本控件
local CFG_WIDGET_BLE    = "t1"     -- 蓝牙开关显示文本控件
local CFG_WIDGET_SSID   = "t2"     -- WiFi 名称（用户输入）
local CFG_WIDGET_PWD    = "t3"     -- WiFi 密码（用户输入）
local CFG_WIDGET_INFO   = "t4"     -- 网络信息提示文本控件
```

**t4 控件显示内容**：

| 模式 | t4 显示内容 |
|------|------------|
| AP | `Connect <SSID>, pwd:<密码>, open http://<IP>` |
| STA（成功） | `Connected <SSID>, open http://<IP>` |
| STA（失败） | 空（t0 显示 "Connect Fail"） |
| OFF | 空 |

**屏幕端控件清单**：

| 控件 | 名称 | 用途 | MCU 写入内容 |
|------|------|------|-------------|
| 文本 | `t0` | WiFi 模式 | `"WiFi热点"` / `"WiFi联网"` / `"WiFi关闭"` |
| 文本 | `t1` | 蓝牙状态 | `"蓝牙开"` / `"蓝牙关"` |
| 按钮 | 任意 | WiFi 关闭 | 触控代码: `printh 70 10 FF FF FF` |
| 按钮 | 任意 | WiFi STA 模式 | 触控代码: `printh 70 11 FF FF FF` |
| 按钮 | 任意 | WiFi AP 模式 | 触控代码: `printh 70 12 FF FF FF` |
| 按钮 | 任意 | 蓝牙开启 | 触控代码: `printh 70 13 FF FF FF` |
| 按钮 | 任意 | 蓝牙关闭 | 触控代码: `printh 70 14 FF FF FF` |
| 按钮 | 任意 | 蜂鸣器测试 | 触控代码: `printh 70 22 FF FF FF` |

**页面初始化事件**（进入设置页时自动刷新）：

```
printh 70 09 FF FF FF
```

## 十二、多设备组网数据结构

> 详见 [多设备组网与训练模式.md](多设备组网与训练模式.md) 第 2 章。

### 12.1 group_info 数据结构

`app_data.lua` 中 `data.group_info` 存储多设备组网信息：

```lua
group_info = {
    -- 自身设备信息（用户可自定义，持久化到 fskv）
    device_name      = "Safex-001",     -- 设备自定义名称
    group_id         = "ALPHA",         -- 所属小组 ID
    group_name       = "阿尔法小队",      -- 小组名称
    is_commander     = false,            -- 是否指挥官（手动指定）
    role             = "member",        -- 角色: "commander" / "member"

    -- 组内成员列表（通过 MQTT 心跳维护）
    members          = {},              -- {[device_id] = {id, name, lat, lng, ...}}
    member_count     = 0,               -- 在线成员数
    commander_online = false,            -- 指挥官是否在线

    -- 指令收发
    last_command     = nil,              -- 最近收到的指令
    timestamp        = 0,
}
```

### 12.2 MQTT 主题定义

| 主题 | 方向 | QoS | 说明 |
|------|------|-----|------|
| `chem/telemetry/<device_id>` | 设备→服务器 | 1 | 定时遥测上报（传感器数据、GNSS、系统状态） |
| `chem/events/<device_id>` | 设备→服务器 | 1 | 报警事件上报（报警触发/清除） |
| `chem/notify` | 服务器→设备 | 1 | 群发通知（所有设备监听） |
| `chem/<device_id>/notify` | 服务器→设备 | 1 | 单发通知（仅指定设备监听） |

### 12.3 遥测上报 payload

设备定时上报到 `chem/telemetry/<device_id>` 主题的 JSON payload（按功能开关过滤）：

```json
{
  "sys": {
    "uptime": 102,
    "device_id": "864793080139046",
    "ntp_synced": false
  },
  "gnss": {
    "lat": 22.5431,
    "lng": 114.0579,
    "speed": 0,
    "fixed": true,
    "timestamp": 1788763200
  },
  "sensor": {
    "pid": {
      "conc": 0.12,
      "voltage": 1.2,
      "alarm": false,
      "timestamp": 1788763200
    },
    "ims": {
      "status": 1,
      "status_desc": "检测",
      "fault": 0,
      "alarm_count": 0,
      "alarm_names": [],
      "timestamp": 1788763200
    },
    "battery": {
      "voltage": 7.6,
      "pct": 86,
      "timestamp": 1788763200
    }
  },
  "alarm": {
    "level": 0,
    "source": "none",
    "sources": [],
    "timestamp": 1788763200
  },
  "rssi": -55,
  "mode": "monitor"
}
```

| 字段 | 说明 | 上报条件 |
|------|------|---------|
| `sys` | 系统信息（device_id, uptime, ntp_synced） | 始终上报 |
| `gnss` | 定位数据（lat, lng, speed, fixed, timestamp） | `gnss_en=true` |
| `sensor.pid` | PID 浓度数据（conc, voltage, alarm, timestamp） | `sensor_report_en` + `sensor_pid_en` |
| `sensor.ims` | IMS 数据（status, status_desc, fault, alarm_count, alarm_names, timestamp） | `sensor_report_en` + `sensor_ims_en` |
| `sensor.battery` | 电池数据（voltage, pct, timestamp） | `sensor_report_en` + `sensor_battery_en` |
| `alarm` | 报警状态（level, source, sources, timestamp） | 始终上报 |
| `rssi` | WiFi 信号强度（dBm） | MQTT 连接时 |
| `mode` | 设备模式（"monitor"） | 始终上报 |

> **注意**：功能关闭的字段不出现在 JSON 中。上报间隔由 `report_interval` 配置（单位：秒，默认 2s）。

### 12.4 报警事件上报 payload

设备触发/清除报警时，即时上报到 `chem/events/<device_id>` 主题：

**报警触发**（`app_data.update_alarm()` 触发）：

IMS 毒剂检测报警示例：
```json
{
  "type": "alarm",
  "data": {
    "source": "ims",
    "level": 3,
    "names": ["DMMP"]
  },
  "device_id": "864793080139046",
  "timestamp": 1788763200000
}
```

PID 浓度超阈值报警示例：
```json
{
  "type": "alarm",
  "data": {
    "source": "pid",
    "level": 2,
    "conc": 1.5,
    "threshold": 1.0
  },
  "device_id": "864793080139046",
  "timestamp": 1788763200000
}
```

**报警清除**（`app_data.clear_alarm()` 触发）：

```json
{
  "type": "clear",
  "data": {
    "source": "ims"
  },
  "device_id": "864793080139046",
  "timestamp": 1788763200000
}
```

| 字段 | 说明 |
|------|------|
| `type` | 事件类型：`alarm`(报警触发) / `clear`(报警清除) |
| `data.source` | 报警来源：`pid` / `ims` / `fall` / `ble` |
| `data.level` | 报警等级（仅 alarm）：0=无 / 2=警告 / 3=危险 |
| `data.names` | 毒剂名称列表（仅 source=ims）：如 `["DMMP"]` |
| `data.conc` | PID 浓度值（仅 source=pid）：单位 ppm |
| `data.threshold` | PID 报警阈值（仅 source=pid）：单位 ppm |
| `device_id` | 设备 IMEI |
| `timestamp` | 毫秒级时间戳 |

### 12.5 下行通知格式

设备订阅两个通知主题：
- `chem/notify` — 群发通知，所有设备监听
- `chem/<device_id>/notify` — 单发通知，仅本设备监听

通知消息按 `type` 字段分发：

**type=locations（已实现）** — 多设备位置快照，`devices` 数组为全量在线设备，缺席即下线：

```json
{
    "type": "locations",
    "timestamp": 1784024217,
    "devices": [
        { "device_id": "860000012345678", "lat": 22.54310, "lng": 113.83615 },
        { "device_id": "860000012345679", "lat": 22.54321, "lng": 113.83620 }
    ]
}
```

| 字段 | 说明 |
|------|------|
| `type` | 固定 `locations` |
| `timestamp` | 快照时间戳，秒级 Unix 时间戳（>1e12 按毫秒归一化），设备端单调递增检查丢弃积压旧快照 |
| `devices` | 全量在线设备数组，最多 8 台，超出截断 |
| `devices[].device_id` | 设备 IMEI |
| `devices[].lat` | 纬度，WGS84 十进制 |
| `devices[].lng` | 经度，WGS84 十进制 |

> **超时守护**：设备端启动超时定时器（`NOTIFY_TIMEOUT`，默认 30 秒，需大于服务器发送周期），每收到一帧有效 notify 消息（快照或旧单条）即重置计时。超时未收到任何 notify 消息则认为周围无设备（服务器停发 / MQTT 断连），自动清空 `app_data.map.devices` 并刷新屏幕标记。

**type=text / config / action（预留，暂未实现）：**

```json
{
    "type": "text",
    "text": "立即撤离",
    "from": "server",
    "timestamp": 1784024217
}
```

| 字段 | 说明 |
|------|------|
| `type` | 通知类型：`text`(文本) / `config`(参数修改) / `action`(动作) |
| `text` | 文本内容（type=text 时） |
| `params` | 参数键值对（type=config 时） |
| `from` | 发送者标识 |
| `timestamp` | Unix 时间戳 |

**单条格式（旧版兼容）** — 无 `type` 字段的单设备坐标消息，`device_id` 从主题（单发）或 payload（群发）提取，坐标支持 `lat`/`lng` 及别名（`latitude`/`lon`/`longitude`）或嵌套 `gnss` 子表。
