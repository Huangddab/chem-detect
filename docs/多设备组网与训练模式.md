## 1. 概述

本文档定义 Safex 便携式化学毒气检测仪的四个新功能模块：

| 编号 | 功能 | 说明 |
|------|------|------|
| 1 | MQTT 多设备组网 | 遗嘱消息 + 通配符订阅 + 手动指定指挥官 + 指令系统 + 远程参数修改 |
| 2 | 屏幕程序对接 | 按照 X5 陶晶池屏幕实际工程，更新控件映射表 |
| 3 | 训练模式 | 网页模拟 GNSS 信号源 + 蓝牙模拟污染源，设备在范围内自动报警 |
| 4 | 多通道报警传递 | 多途径传递报警数据（本文档留空，后续补充） |

### 1.1 现有架构基础

```
本系统采用星型架构，app_data 是中心节点：
- 各模块只与 app_data 交互，模块间禁止直接 require
- 数据交换通过 app_data.get()（只读快照）/ app_data.update_xxx()（写入）
- 模块间功能调用通过 app_data.register_callback() / get_callback() 中介
- 模块联动通过 sys.publish() 事件广播
- MQTT 模块 (mod_mqtt.lua) 已实现基础连接和发布/订阅
- BLE 模块 (mod_ble.lua) 已实现设备扫描
- GNSS 模块 (mod_gnss.lua) 已实现定位
- 报警管理器 (mod_alarm.lua) 已实现多源报警聚合
```

## 2. MQTT 多设备组网

### 2.1 设计目标

- 多台 Safex 设备通过 MQTT 服务器互相感知
- 每台设备定时上报自身状态（GNSS 坐标 + 报警信息 + 组信息）
- 通过遗嘱消息感知设备离线
- 通过通配符订阅接收所有设备的状态
- **手动指定指挥官**：用户通过 Web 界面或屏幕指定某台设备为指挥官
- **指挥官指令系统**：指挥官可向单台设备、指定小组或全网发送文本指令
- **远程参数修改**：指挥官可远程修改成员设备的配置参数
- QoS 0 + 紧凑 payload，降低 4G 流量消耗

### 2.2 设备身份与分组

每台设备拥有自定义身份信息，持久化到 fskv，掉电不丢失：

| 字段 | 说明 | 示例 |
|------|------|------|
| `device_name` | 设备自定义名称 | `"Safex-001"` |
| `group_id` | 所属小组 ID | `"ALPHA"` |
| `group_name` | 小组名称 | `"阿尔法小队"` |
| `is_commander` | 是否为指挥官（手动指定） | `true` / `false` |
| `role` | 角色 | `"commander"` / `"member"` |

**默认值**：
- `device_name` = `"Safex-<IMEI后6位>"`（自动生成）
- `group_id` = `"DEFAULT"`
- `group_name` = `"默认小队"`
- `is_commander` = `false`
- `role` = `"member"`

**配置方式**：
1. Web 界面「组网」页面设置（主要方式）
2. 屏幕设置页配置（预留）
3. MQTT 下行指令修改（指挥官远程修改成员参数）

### 2.3 指挥官角色

#### 2.3.1 手动指定原则

- 指挥官由用户**手动指定**，不自动选举
- 一台设备是否为指挥官，由 `is_commander` 配置项决定
- 指挥官拥有以下权限：
  - 发送文本指令（单设备/小组/全网）
  - 远程修改成员设备参数
  - 查看全组成员实时状态
- 非指挥官设备（`is_commander=false`）只能上报状态，不能发送指令

#### 2.3.2 指挥官离线处理

- 指挥官离线时，组内**不自动选举**新指挥官
- 其他设备在屏幕/Web 上显示「指挥官离线」状态
- 需用户手动将另一台设备指定为指挥官
- 指挥官重新上线后自动恢复指令发送能力

#### 2.3.3 安全策略

> **当前版本不实现指令签名验证**，后续版本可扩展。

- 当前仅靠 `is_commander` 标志位控制发送权限
- MQTT Topic 层面：只有 `is_commander=true` 的设备才会发布到指令 Topic
- 接收端不验证发送者身份，默认信任同组消息
- 后续可增加指令密码或 token 验证

### 2.4 MQTT Topic 设计

| Topic | 方向 | 说明 |
|-------|------|------|
| `safex/<device_id>/status` | 发布 | 设备定时上报自身状态（含组信息） |
| `safex/<device_id>/offline` | 遗嘱 | 设备异常离线时自动发布 |
| `safex/+/status` | 订阅 | 通配符订阅所有设备状态 |
| `safex/+/offline` | 订阅 | 通配符订阅所有设备离线通知 |
| `safex/group/<group_id>/cmd` | 订阅 | 接收组内下行指令（全组成员订阅） |
| `safex/group/<group_id>/cmd` | 发布 | 指挥官发布指令（仅 is_commander=true） |

- `<device_id>` = 设备 IMEI（如 `864793080139046`）
- `<group_id>` = 小组 ID（如 `ALPHA`）
- 遗嘱消息 QoS = 0，payload = `{"id":"<device_id>","offline":1}`
- 指令 Topic QoS = 1（确保送达），不保留消息

### 2.5 状态上报 Payload 格式

为降低 4G 流量，payload 使用短字段名，QoS 0，不保留消息：

```json
{
    "id": "864793080139046",
    "dn": "Safex-001",
    "gid": "ALPHA",
    "gn": "阿尔法小队",
    "cmd": false,
    "lat": 39.9042,
    "lng": 116.4074,
    "fix": 1,
    "al": 0,
    "src": "",
    "conc": 0,
    "sub": "",
    "rng": 0,
    "ts": 1784024217
}
```

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | string | 设备 IMEI | `"864793080139046"` |
| `dn` | string | 设备自定义名称 | `"Safex-001"` |
| `gid` | string | 小组 ID | `"ALPHA"` |
| `gn` | string | 小组名称 | `"阿尔法小队"` |
| `cmd` | bool | 是否指挥官 | `false` |
| `lat` | number | 纬度（6位小数），0=未定位 | `39.904200` |
| `lng` | number | 经度（6位小数），0=未定位 | `116.407400` |
| `fix` | number | 定位状态：0=未定位，1=已定位 | `1` |
| `al` | number | 报警等级：0=正常，2=警告，3=严重 | `3` |
| `src` | string | 报警来源（空=无报警） | `"pid"` |
| `conc` | number | 浓度值（ppm），无报警时为 0 | `25.6` |
| `sub` | string | 报警物质名称（空=无报警） | `"苯"` |
| `rng` | number | 报警范围（米），0=未知/单设备 | `350` |
| `ts` | number | Unix 时间戳（秒） | `1784024217` |

**Payload 大小估算**：约 150-180 字节/条，每 3 秒一条，日均流量约 4.3MB。

### 2.6 指挥官指令系统

#### 2.6.1 指令 JSON 格式

指挥官通过 `safex/group/<group_id>/cmd` Topic 发布指令：

```json
{
    "type": "text",
    "target": "all",
    "text": "立即撤离",
    "from": "864793080139046",
    "from_name": "Safex-001",
    "timestamp": 1784024217
}
```

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `type` | string | 指令类型：`text`/`config`/`action` | `"text"` |
| `target` | string | 目标范围 | `"device:864793080139047"` / `"group:ALPHA"` / `"all"` |
| `text` | string | 文本指令内容（type=text 时有效） | `"立即撤离"` |
| `params` | object | 参数键值对（type=config 时有效） | `{"alarm_en": true}` |
| `from` | string | 发送者 IMEI | `"864793080139046"` |
| `from_name` | string | 发送者名称 | `"Safex-001"` |
| `timestamp` | number | Unix 时间戳（秒） | `1784024217` |

#### 2.6.2 指令类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `text` | 文本指令 | `"立即撤离"`、`"前往坐标 39.90,116.40"`、`"开启静默模式"` |
| `config` | 远程修改参数 | `{"params": {"alarm_en": true, "report_interval": 5}}` |
| `action` | 动作指令 | `{"params": {"action": "silence"}}` 或 `{"params": {"action": "restart"}}` |

#### 2.6.3 目标范围

| target 格式 | 说明 | 执行条件 |
|------------|------|---------|
| `device:<IMEI>` | 指定单台设备 | 仅目标 IMEI 匹配的设备执行 |
| `group:<GROUP_ID>` | 指定小组 | 仅同组（`group_id` 匹配）的设备执行 |
| `all` | 全网 | 所有收到指令的设备执行（跨组） |

#### 2.6.4 指令接收流程

```
设备收到 safex/group/<group_id>/cmd 消息
    │
    ▼
解析 JSON → 提取 target 字段
    │
    ▼
判断是否为自身目标？
    │
    ├─ target = "device:<自己的IMEI>" → 执行
    ├─ target = "group:<自己的group_id>" → 执行
    ├─ target = "all" → 执行
    └─ 其他 → 忽略
    │
    ▼
按 type 执行：
    ├─ text  → 存入 group_info.last_command，屏幕显示
    ├─ config → 调用 app_data.set_config(key, value) 逐项修改
    └─ action → 执行动作（silence/restart 等）
```

#### 2.6.5 预置文本指令

| 指令文本 | 设备端行为 |
|---------|---------|
| `立即撤离` | 屏幕弹出红色警告 + 蜂鸣器急促鸣响 |
| `前往坐标 X,Y` | 屏幕显示目标坐标 + 导航箭头（预留） |
| `开启静默模式` | 关闭蜂鸣器 + 关闭 LED + 关闭屏幕背光 |
| `解除静默模式` | 恢复蜂鸣器 + LED + 屏幕背光 |
| `全员集合` | 屏幕显示集合指令 + 蜂鸣器短鸣 |

> 预置指令在 `mod_mqtt.lua` 中通过 `COMMAND_HANDLERS` 路由表处理，可扩展。

#### 2.6.6 远程参数修改（config 类型）

指挥官可远程修改成员设备的任意 `config` 配置项：

```json
{
    "type": "config",
    "target": "group:ALPHA",
    "params": {
        "alarm_en": true,
        "report_interval": 5,
        "buzzer_en": false
    },
    "from": "864793080139046",
    "from_name": "Safex-001",
    "timestamp": 1784024217
}
```

**处理逻辑**：
1. 遍历 `params` 键值对
2. 对每个键调用 `app_data.set_config(key, value)`
3. `set_config` 自动完成类型转换、持久化到 fskv
4. 无法识别的配置项跳过并记录日志

**安全限制**：
- 不可远程修改 `mqtt_server`、`mqtt_port`、`ota_url`（防止断网/断 OTA）
- 不可远程修改 `net_mode`（防止网络模式切换导致掉线）
- 不可远程关闭 `mqtt_en`（防止设备失联）

#### 2.6.7 动作指令（action 类型）

| action 值 | 行为 |
|-----------|------|
| `silence` | 进入静默模式（关蜂鸣器 + 关 LED + 关背光） |
| `unsilence` | 解除静默模式 |
| `restart` | 系统重启（`sys.restart()`） |

### 2.7 上报间隔

- 默认 3 秒（通过 `report_interval` 配置）
- 报警时自动加速为 2 秒
- 正常无报警时可配置为 5-10 秒以省流
- 指挥官离线时组内设备保持正常上报

### 2.8 组内设备列表管理

每台设备维护一个本地组内成员表 `group_info.members`：

```lua
members = {
    ["864793080139046"] = {
        id           = "864793080139046",
        name         = "Safex-001",
        group_id     = "ALPHA",
        group_name   = "阿尔法小队",
        is_commander = true,
        lat          = 39.9042,
        lng          = 116.4074,
        fixed        = true,
        alarm_level  = 0,
        alarm_source = "",
        concentration = 0,
        substance    = "",
        range        = 0,
        online       = true,
        last_seen    = 1784024217,  -- 最后收到消息的时间
    },
    -- ... 其他成员
}
```

- **过滤机制**：只维护**同组**（`group_id` 相同）的设备，不同组的设备状态丢弃
- **老化机制**：超过 15 秒未收到消息的设备标记为离线
- **列表上限**：最多 50 台设备，超出按 `last_seen` 淘汰最旧的
- **遗嘱处理**：收到 `offline` 消息立即标记离线
- **指挥官状态**：成员表中 `is_commander=true` 的设备标识为指挥官

### 2.9 报警范围计算

当组内有多台设备同时报警时，计算报警范围：

**算法**：
1. 收集所有 `al > 0` 的在线同组成员
2. 若只有 1 台设备报警 → `rng = 0`（范围未知）
3. 若有 2 台以上设备报警 → 找出距离最远的两台设备，距离 = 报警范围
4. 中心 GNSS = 所有报警设备的地理中心点

**距离计算**（Haversine 公式简化版）：
```
d = 6371000 * acos(sin(lat1)*sin(lat2) + cos(lat1)*cos(lat2)*cos(lng2-lng1))
```
单位：米，地球半径取 6371000m。

**中心点计算**：
```
center_lat = avg(lat1, lat2, ..., latN)
center_lng = avg(lng1, lng2, ..., lngN)
```

**上报内容**：
- 每台报警设备上报的 `rng` = 计算出的最远距离
- `lat`/`lng` = 自身坐标（不是中心点，中心点由接收端计算）

### 2.16 组网工作流程

#### 2.16.1 设备上线

```
设备启动 → 初始化 MQTT → 连接服务器
    │
    ▼
设置遗嘱消息 (safex/<IMEI>/offline)
    │
    ▼
订阅:
  - safex/+/status   （所有设备状态）
  - safex/+/offline   （所有离线通知）
  - safex/group/<group_id>/cmd  （组内指令）
    │
    ▼
首次发布状态到 safex/<IMEI>/status
  payload 含: id, dn, gid, gn, cmd, lat, lng, fix, al, src, conc, sub, rng, ts
    │
    ▼
进入定时上报循环（每 report_interval 秒发布一次）
```

#### 2.16.2 指挥官发送指令

```
用户在 Web 界面填写指令 → POST /group/command
    │
    ▼
检查 is_commander=true？
    ├─ 否 → 返回 403 错误
    └─ 是 ↓
    │
    ▼
构造指令 JSON（添加 from, from_name, timestamp）
    │
    ▼
发布到 safex/group/<group_id>/cmd (QoS 1)
    │
    ▼
返回成功响应
```

#### 2.16.3 设备接收指令

```
收到 safex/group/<group_id>/cmd 消息
    │
    ▼
解析 JSON
    │
    ▼
检查 net_cmd_en 开关？
    ├─ 关闭 → 忽略指令，记录日志
    └─ 开启 ↓
    │
    ▼

  ├─ "group:<自己的group_id>" → 执行
  ├─ "all" → 执行
  └─ 其他 → 忽略
    │
    ▼
按 type 执行：
  ├─ text  → 存入 last_command，sys.publish("GROUP_CMD", cmd) 通知屏幕显示
  ├─ config → 遍历 params 调用 set_config（排除安全限制项）
```

## 4. 训练模式

### 4.1 设计目标

在网页 OTA 界面新增"训练模式"入口，支持两种模拟污染源：

1. **GNSS 模拟源** — 设置虚拟污染源坐标和影响范围，设备进入范围即报警
2. **蓝牙模拟源** — 配置指定 BLE 设备的 MAC 地址，通过 RSSI 和广播数据模拟污染源和浓度

### 4.2 训练模式总开关

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `training_en` | bool | false | 训练模式总开关 |
| `training_type` | string | "gnss" | 训练类型："gnss" / "ble" / "both" |

- 训练模式开启后，模拟报警数据写入 `data.alarm`，走正常报警流程
- 报警来源标记为 `"gnss_sim"` 或 `"ble_sim"`，与真实传感器区分
- 训练模式下真实传感器仍正常工作，报警合并

### 4.3 GNSS 模拟源

#### 4.3.1 配置

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `training_gnss_lat` | number | 0 | 模拟源纬度 |
| `training_gnss_lng` | number | 0 | 模拟源经度 |
| `training_gnss_range` | number | 100 | 模拟源影响范围（米） |
| `training_gnss_substance` | string | "模拟毒剂" | 模拟物质名称 |
| `training_gnss_conc` | number | 50 | 模拟浓度（ppm） |

#### 4.3.2 报警逻辑

```
1. 获取自身 GNSS 坐标 (lat_self, lng_self)
2. 计算到模拟源的距离: dist = haversine(lat_self, lng_self, sim_lat, sim_lng)
3. 若 dist <= training_gnss_range:
   - 触发报警: level=3, source="gnss_sim", substance=配置值, conc=配置值
4. 若 dist > training_gnss_range:
   - 不报警（清除 gnss_sim 来源的报警）
```

#### 4.3.3 网页配置界面

在 `ota.html` 新增"训练模式"页面：
- 输入模拟源坐标（纬度、经度）
- 输入影响范围（米）
- 输入模拟物质名称和浓度
- "开始模拟" / "停止模拟" 按钮
- 实时显示设备自身坐标和到模拟源的距离
- 距离 < 范围时显示红色报警状态

### 4.4 蓝牙模拟源

#### 4.4.1 配置

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `training_ble_mac` | string | "" | 模拟源 BLE MAC 地址 |
| `training_ble_name` | string | "" | 模拟源 BLE 名称（可选，与 MAC 二选一） |
| `training_ble_rssi_thr` | number | -60 | RSSI 阈值，信号强于此值才模拟 |
| `training_ble_substance` | string | "模拟毒剂" | 模拟物质名称 |
| `training_ble_conc_max` | number | 100 | 最大模拟浓度（RSSI 最强时） |
| `training_ble_conc_min` | number | 10 | 最小模拟浓度（RSSI 阈值时） |

#### 4.4.2 浓度计算

RSSI 越强（绝对值越小），模拟浓度越高：

```
浓度 = conc_min + (conc_max - conc_min) * (rssi_thr - |rssi|) / |rssi_thr|
```

- RSSI = 阈值时 → 浓度 = `conc_min`
- RSSI = 0（最强）时 → 浓度 = `conc_max`
- RSSI 弱于阈值 → 不报警

#### 4.4.3 广播数据解析

BLE 广播数据中可编码额外信息：

| 广播数据格式 | 解析方式 |
|-------------|---------|
| Manufacturer Data | 可编码物质类型（2字节）+ 浓度系数（2字节） |
| Service UUID | 可标识不同的模拟源类型 |
| Local Name | 可直接包含物质名称 |

当前方案：优先从广播数据解析物质和浓度，解析失败时使用配置的默认值。

#### 4.4.4 报警逻辑

```
1. BLE 扫描到指定 MAC 或名称的设备
2. 检查 RSSI 是否强于阈值 (rssi > rssi_thr，注意 RSSI 是负值)
3. 若 RSSI <= rssi_thr: 不报警
4. 若 RSSI > rssi_thr:
   a. 尝试从广播数据解析物质和浓度
   b. 解析失败时用 RSSI 计算浓度
   c. 触发报警: level=3, source="ble_sim", substance=解析值, conc=计算值
5. 未扫到目标设备: 清除 ble_sim 来源的报警
```

### 4.5 训练模式与 MQTT 组网联动

- 训练模式下，模拟报警通过 MQTT 正常上报
- 其他设备收到 `src="gnss_sim"` 或 `src="ble_sim"` 的报警时，屏幕显示"训练"标识
- 训练模式的模拟源配置可通过 MQTT 下发（`safex/<device_id>/cmd` topic）

### 4.6 新增数据结构

在 `app_data.lua` 的 `data` 表中新增：

```lua

    enabled = false,
    type = "gnss",              -- "gnss" / "ble" / "both"
    -- GNSS 模拟源
    gnss_sim = {
        lat = 0,
        lng = 0,
        range = 100,
        substance = "模拟毒剂",
        conc = 50,
        active = false,          -- 当前是否在范围内（是否报警中）
```
